# Platform findings

Checked 2026-09-09. These are implementation constraints, not a claim that any provider endorses this product.

- **Discord:** [Self-bot policy](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots) says automation of ordinary user accounts outside OAuth2/bot APIs is forbidden. The product uses a bot, so it cannot read conversations the bot cannot access. [Gateway events](https://docs.discord.com/developers/events/gateway-events#message-create) define create/update/delete delivery, and message content access requires the relevant privileged intent. Partial updates may omit text; the companion does not manufacture a new empty revision for metadata-only events.
- **Telegram:** [API edit updates](https://core.telegram.org/constructor/updateEditMessage) expose the new message; [delete updates](https://core.telegram.org/constructor/updateDeleteMessages) can contain only message IDs. The collector uses account-scoped IDs for non-channel chats and separate scopes for channels so chat-less deletes can match previous captures. [Telethon's event documentation](https://docs.telethon.dev/en/stable/modules/events.html#telethon.events.messagedeleted.MessageDeleted) notes that deletion updates are not always delivered. The implementation uses the maintained [teleproto library](https://docs.teleproto.dev/migrating-from-gramjs). [Telegram API terms](https://core.telegram.org/api/terms) require care for privacy and prohibit preventing self-destructing content from disappearing; that content is excluded here. Ordinary-message archival still needs product/terms review before broad commercial distribution.
- **Signal:** [Signal's linked-device architecture](https://signal.org/blog/a-synchronized-start-for-linked-devices/) makes a linked device the endpoint that can read messages. There is no Signal-hosted archive API implemented here. The companion uses the unofficial [signal-cli JSON-RPC interface](https://github.com/AsamK/signal-cli/blob/master/man/signal-cli-jsonrpc.5.adoc), including startLink, finishLink, incoming envelopes, edit messages and remoteDelete timestamps. Pairing is explicit and isolated from existing Signal desktop state.
- **WhatsApp:** The implementation uses the unofficial [Baileys project](https://github.com/WhiskeySockets/Baileys), not Meta's Business Platform. Baileys emits an edited-message wrapper for edits and a revoke message stub on `messages.update`. The normalizer distinguishes these from delivery receipts and reactions. This route can break as the protocol changes and has account-policy risks. Business APIs should not be presented as providing universal access to a person's private WhatsApp chats.

Across all four platforms, the useful product promise is a record of versions **received by a running, authorized collector**. No software can reconstruct an unseen earlier revision from a later deletion notice alone. Attachments are represented by metadata in this version; media downloads and additional content types require separate implementation.
